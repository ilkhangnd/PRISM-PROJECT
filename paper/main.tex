\begin{abstract}
Audits of Ethereum Virtual Machine (EVM) smart contracts increasingly rely on large language models (LLMs), but sending unreleased contract source code to cloud-hosted models exposes proprietary business logic, while rule-based analyzers flood auditors with alarms and fuzzers struggle to reach deep states without guidance. We present \textbf{PRISM}, an audit pipeline that runs entirely on local infrastructure and combines (i)~reversible identifier pseudonymization (\textit{DataMasker}), (ii)~a function-level code property graph (CPG) built from Slither's static single assignment (SSA) intermediate representation (IR), (iii)~an edge-aware multi-head graph attention classifier (\textit{GNNMHAv2}) that ranks functions for (iv)~an open-weight quantized LLM that writes Foundry invariant harnesses, and (v)~EVM execution and template-based patch checking. On 12,991 function graphs covering five Smart Contract Weakness Classification (SWC) classes, GNNMHAv2 reaches 74.09\% accuracy and 75.77\% macro-F1 on a held-out test set of 1,949 graphs, and 75.75\% macro-F1 when the 28 test contract families share no family with training. On a 57-contract benchmark, DataMasker keeps every contract compilable and every Slither finding reproducible, while restricting Slither output to the target taxonomy and to state-mutating findings lowers the share of safe contracts with any alarm from 27/27 to 6/27. We also quantify what pseudonymization does \emph{not} hide: 89.5\% of identifiers remain linkable through token-frequency analysis, which is why PRISM keeps all inference local.

\keywords{Smart contract security \and Graph neural networks \and Large language models \and Invariant fuzzing \and Privacy-preserving analysis.}
\end{abstract}

\section{Introduction}
\label{sec:intro}

Smart contracts on the Ethereum Virtual Machine (EVM) hold large amounts of value in decentralized finance, and deployed bytecode cannot be patched in place~\cite{luu2016making,atzei2017survey}. Incidents from The DAO to repeated flash-loan manipulations show that flaws must be found before deployment~\cite{atzei2017survey,kushwaha2022systematic}.

Automated auditing has relied on two paradigms~\cite{kushwaha2022systematic,zhu2024survey,alsunaidi2025leveraging}. Static analyzers such as Slither~\cite{feist2019slither} and Securify~\cite{tsankov2018securify} match intermediate representations (IRs) against expert rules; they are fast but imprecise. In a study of 47,587 contracts, 97\% were flagged as vulnerable by at least one tool, indicating a large number of false positives~\cite{durieux2020empirical}, and bug-injection studies confirm both missed bugs and spurious alarms~\cite{ghaleb2020solidifi}. Dynamic fuzzers~\cite{jiang2018contractfuzzer,grieco2020echidna,nguyen2020sfuzz,wustholz2020harvey,choi2021smartian,shou2023ityfuzz} produce concrete execution witnesses but must satisfy narrow guards to reach vulnerable states.

Graph neural network (GNN) detectors~\cite{zhuang2021smart,liu2023cge,zhen2024dagnn,pang2025graph,nguyen2025mando} and auditors built on large language models (LLMs)~\cite{sun2024gptscan,wei2024llm,liu2025propertygpt,gai2026llama,lin2025promfuzz} close part of this gap. Most LLM-based systems, however, call hosted models such as GPT-4~\cite{sun2024gptscan,liu2025propertygpt}, which means transmitting unreleased source code to a third party. Confidential inference on the provider side is an active research topic~\cite{li2024confidential} but is not yet available to typical audit teams. Open-weight models fine-tuned for vulnerability detection~\cite{mandana2025evullm} show that local inference is feasible, but they classify code rather than produce executable evidence, and they do not analyze what a local pipeline still leaks when its artifacts (prompts, logs, harnesses) are shared.

PRISM addresses this setting. It is a pipeline that never sends code off the audit host and that uses each component for what it does well: a graph classifier to rank functions cheaply, an open-weight LLM to write targeted invariant harnesses for the ranked functions, and the EVM to confirm or reject each hypothesis. Our contributions are:

\begin{itemize}
\item \textbf{A local audit pipeline} (Sect.~\ref{sec:method}) that chains reversible pseudonymization, code property graph (CPG) extraction, graph-based screening, local LLM harness generation, Foundry execution, and patch checking, with an explicit threat model (Sect.~\ref{sec:threat}).
\item \textbf{GNNMHAv2}, an edge-aware graph attention classifier over a function-level CPG with typed control- and data-flow edges, jumping-knowledge (JK) readout, and focal loss. It achieves $76.31\% \pm 0.06\%$ macro-F1 across five seeds on a strict lineage-disjoint split and provides $0.21$\,ms function ranking latency before dynamic execution (Sect.~\ref{sec:rq1}).
\item \textbf{A fidelity and exposure analysis of pseudonymization}: DataMasker preserves compilability (57/57) and Slither findings (229/229), and we measure its residual exposure to dictionary (30.4\%) and token-frequency (89.5\%) linkage attacks (Sect.~\ref{sec:rq3}).
\item \textbf{An EVM-level validation study} of harness execution (300 runs, 30 seeds), alarm filtering on 57 contracts reducing false alarms on safe contracts to 0\%, and five-check validation of template patches (Sects.~\ref{sec:rq2}--\ref{sec:rq5}).
\end{itemize}
The remainder of this paper is organized as follows. Sect.~\ref{sec:related} reviews related work, Sect.~\ref{sec:method} presents the threat model and design, Sect.~\ref{sec:setup} describes the experimental setup, Sect.~\ref{sec:results} answers five research questions, Sect.~\ref{sec:discussion} discusses the findings, and Sect.~\ref{sec:conclusion} concludes the paper.

\section{Related Work}
\label{sec:related}

\subsubsection{Static analysis and verification.}
Oyente~\cite{luu2016making} applies symbolic execution with satisfiability modulo theories (SMT) solving; Securify~\cite{tsankov2018securify} checks compliance and violation patterns in Datalog; Slither~\cite{feist2019slither} lifts Solidity to a static single assignment (SSA) IR, SlithIR, and runs rule-based detectors. Empirical studies report low precision and uneven recall across these tools~\cite{durieux2020empirical,ghaleb2020solidifi}.

\subsubsection{Fuzzing.}
ContractFuzzer~\cite{jiang2018contractfuzzer} monitors call-level oracles, Echidna~\cite{grieco2020echidna} and sFuzz~\cite{nguyen2020sfuzz} perform property-based and adaptive fuzzing, Harvey~\cite{wustholz2020harvey} and Smartian~\cite{choi2021smartian} add greybox and data-flow guidance, and ItyFuzz~\cite{shou2023ityfuzz} fuzzes from state snapshots.

\subsubsection{Graph learning.}
Zhuang et al.~\cite{zhuang2021smart} and Liu et al.~\cite{liu2023cge} learn over contract graphs with normalized nodes and expert patterns; DA-GNN~\cite{zhen2024dagnn} applies dual attention; ConSense~\cite{pang2025graph} combines local and global attention; MANDO-LLM~\cite{nguyen2025mando} feeds LLM code features into heterogeneous graph transformers. PRISM's classifier builds on GAT/GATv2~\cite{velickovic2018graph,brody2022attentive} and differs in operating on a homogeneous SSA-level function graph with typed edge attributes. Its role is to rank functions for the LLM stage, not to be the final verdict.

\subsubsection{LLMs for auditing, fuzzing, and repair.}
GPTScan~\cite{sun2024gptscan} pairs GPT with static confirmation; PropertyGPT~\cite{liu2025propertygpt} and SmartInv~\cite{wang2024smartinv} generate properties or invariants for verification; LLM4Fuzz~\cite{shou2024llm4fuzz}, LLAMA~\cite{gai2026llama} and PromFuzz~\cite{lin2025promfuzz} use LLMs to guide fuzzing; LLM-SmartAudit~\cite{wei2024llm} uses multi-agent conversation. EVuLLM~\cite{mandana2025evullm} fine-tunes small open-weight models with QLoRA. On repair, sGuard~\cite{nguyen2021sguard} and Elysium~\cite{torres2022elysium} patch source or bytecode with templates, and LLM-based program repair is surveyed in~\cite{yang2025survey}. Table~\ref{tab:positioning} positions PRISM: it is not the strongest detector or fuzzer in isolation. Its contribution is combining ranking, local harness generation and execution under an explicit confidentiality constraint.

Figure~\ref{fig:pipeline} shows the five stages. All stages run on the audit host; no network access is required after the model weights are installed.

\subsection{Threat Model and Pseudonymization}
\label{sec:threat}

\textit{Assets and trust boundary.} The asset is unreleased contract source code together with the business logic it reveals (identifier names, constants, addresses, endpoints). The trust boundary is the audit host operated by the contract owner or its auditor.

\textit{Adversaries.} We consider (A1) third-party model providers and network observers, which a cloud-LLM workflow would expose code to; and (A2) honest-but-curious parties that later see PRISM \emph{artifacts} outside the host, such as prompt logs, generated harnesses, bug reports shared with external reviewers, or a shared inference server inside the organization. PRISM removes A1 by construction (no remote inference). DataMasker reduces what A2 learns from artifacts. A fully compromised audit host is out of scope, because such an adversary can read the plaintext source directly.

\textit{Mechanism.} \textit{PrivacyFilter} first removes hard-coded keys, remote procedure call (RPC) endpoints, and 20-byte addresses. \textit{DataMasker} then renames user-defined identifiers while preserving Solidity keywords, EVM built-ins such as \texttt{msg.sender} and \texttt{block.timestamp}, and standard interfaces (e.g., \texttt{IERC20}). Each identifier $x_i$ of syntactic kind $\kappa(x_i)\in\{\text{type},\text{function},\text{variable}\}$ is mapped deterministically to
\begin{equation}
\mathcal{T}(x_i) = \texttt{prism\_}\kappa(x_i)\texttt{\_}\langle i\rangle,
\end{equation}
where $\langle i\rangle$ is a zero-padded counter. The inverse table $\mathcal{T}^{-1}$ is kept only in process memory and is used to restore names in the final report. Sect.~\ref{sec:rq3} measures both fidelity and the residual linkage risk against A2.

\subsection{Function-Level Code Property Graph}

From the pseudonymized source $S_{\mathit{mask}}$, PRISM extracts Slither's SSA IR~\cite{feist2019slither} and builds one directed graph per function, $\mathcal{G}=(\mathcal{V},\mathcal{E},X,E_{\mathit{attr}})$, whose nodes are SSA instructions.
\begin{itemize}
\item \textbf{Node features} $X\in\mathbb{R}^{N\times 32}$: a 13-dimensional one-hot instruction type, 10 security indicators (low-level calls, storage reads and writes, guards, transaction-context reads, etc.), and 9 structural attributes (in- and out-degree, loop membership, relative depth, etc.).
\item \textbf{Edge attributes} $E_{\mathit{attr}}\in\{0,1\}^{|\mathcal{E}|\times 4}$: a one-hot edge type among \texttt{sequential}, \texttt{branch}, \texttt{loop\_back} (control flow) and \texttt{data\_dep} (def-use), so control and data flow share one edge set.
\end{itemize}

\subsection{GNNMHAv2 Classifier}

GNNMHAv2 stacks $L=4$ edge-aware graph attention layers with $K=8$ heads and hidden size $d=256$~\cite{velickovic2018graph,brody2022attentive}. With $\tilde{\mathbf{e}}_{ij}=W_e\mathbf{e}_{ij}$ the projected edge attribute and $\mathcal{N}^{+}(i)=\mathcal{N}(i)\cup\{i\}$, head $k$ of layer $l$ computes
\begin{equation}
\alpha_{ij}^{k,l}=\operatorname*{softmax}_{j\in\mathcal{N}^{+}(i)}\Big(\mathrm{LeakyReLU}\big(\mathbf{a}_{s}^{k\top}W^{k,l}h_i^{l}+\mathbf{a}_{t}^{k\top}W^{k,l}h_j^{l}+\mathbf{a}_{e}^{k\top}\tilde{\mathbf{e}}_{ij}\big)\Big),
\end{equation}
\begin{equation}
h_i^{l+1}=\mathrm{ELU}\Big(\mathrm{BN}\Big(\tfrac{1}{K}\textstyle\sum_{k=1}^{K}\sum_{j\in\mathcal{N}^{+}(i)}\alpha_{ij}^{k,l}\,W^{k,l}h_j^{l}\Big)\Big)+h_i^{l}.
\end{equation}
where BN is batch normalization and ELU the exponential linear unit.
Residual connections and a jumping-knowledge readout, $z_i=[h_i^{1}\|h_i^{2}\|h_i^{3}\|h_i^{4}]\in\mathbb{R}^{1024}$, limit over-smoothing and keep both local and multi-hop patterns. The graph embedding $g\in\mathbb{R}^{2048}$ concatenates attention pooling and mean pooling:
\begin{equation}
g=\Big[\textstyle\sum_{i}\beta_i z_i \,\Big\|\, \frac{1}{N}\sum_i z_i\Big],\qquad \beta_i=\operatorname*{softmax}_i\big(\mathbf{w}^{\top}\tanh(W_p z_i)\big).
\end{equation}
Training uses class-weighted focal loss (built on label-smoothed cross-entropy, CE) with label smoothing $\epsilon=0.05$ and $\gamma=2$:
\begin{equation}
\mathcal{L}=\frac{1}{n}\sum_{m=1}^{n}\alpha_{y_m}(1-p_{m})^{\gamma}\,\mathrm{CE}_{\epsilon}(g_m,y_m),
\end{equation}
where $p_m$ is the predicted probability of the true class. One layer costs $O(K(|\mathcal{V}|d^2+|\mathcal{E}|d))$, i.e., linear in graph size for fixed $d$.

\textit{Two-stage screening.} A binary screening model (Stage~A) first separates vulnerable from safe functions; only functions it flags are passed to the five-class model (Stage~B) and ranked by risk score $\Phi$.

\subsection{Local LLM Harness Generation, Execution, and Repair}

Functions with $\Phi\ge 0.5$ are packaged by \textit{PromptBuilder} into a structured prompt containing the masked function, its hotspot lines, a Slither topology summary, and three few-shot harness examples. An open-weight code LLM (DeepSeek-Coder-V2-Lite, a 16B-parameter mixture-of-experts with 2.4B active parameters~\cite{deepseek2024coderv2}, 4-bit \texttt{Q4\_K\_M} GGUF via llama.cpp\footnote{\url{https://github.com/ggml-org/llama.cpp}}) writes a Foundry test contract inheriting \texttt{forge-std/Test.sol}. Generation uses a context window of 4,096 tokens, temperature 0.2, top-$p$ 0.95, and a budget of up to three compiler-feedback repair retries, requiring only 5.8\,GB of unified memory.

Foundry Forge runs each harness in a local EVM with up to 10,000 invariant-fuzzing calls. A finding is \emph{confirmed} only if an assertion fails with a concrete counterexample trace; otherwise it is reported as unconfirmed. For confirmed findings, a template-based repair module proposes a patch that must pass five checks (Sect.~\ref{sec:rq5}). Identifiers are restored through $\mathcal{T}^{-1}$ only in the final report.

\section{Experimental Setup}
\label{sec:setup}

\subsubsection{Research questions (RQs).}
\textbf{RQ1}: How accurately does GNNMHAv2 classify vulnerable functions, including on unseen contract families?
\textbf{RQ2}: Do harnesses execute reliably and reproducibly on the local EVM?
\textbf{RQ3}: Does pseudonymization preserve analysis utility, and what does it still leak?
\textbf{RQ4}: How much does PRISM's filtering reduce alarms on safe contracts?
\textbf{RQ5}: Do synthesized patches block exploits while preserving interfaces?

\subsubsection{Dataset.}
We extract 12,991 canonical function-level CPGs with at least three nodes from three established repositories: SmartBugs Wild~\cite{durieux2020empirical} (1,179 V2 graphs), the SolidiFI Benchmark~\cite{ghaleb2020solidifi} (8,105 graphs), and LISA-Bench (3,707 graphs). They span five major classes of the Smart Contract Weakness Classification (SWC) registry: Reentrancy (SWC-107, 2,475), Integer Overflow (SWC-101, 2,392), Access Control (SWC-105, 2,026), Unchecked Return Value (SWC-104, 2,983), and Transaction-Order Dependence / front-running (SWC-114, 3,115).
Labels are assigned under a \emph{contract-derived weak supervision} policy. In an audit of all 350 SolidiFI BugLog contracts, 4,928 of 9,369 synthetic injection spans mapped uniquely to lexical function bodies, while 4,441 spans either spanned multiple functions or lacked unambiguous lexical demarcation. To preserve statistical support without introducing arbitrary truncation, function graphs inherit their parent contract vulnerability label, with resulting label noise treated as an explicit threat to validity. Stage-A screening relies on 3,669 binary CPGs (3,132 vulnerable, 537 verified safe) built from ground-truth verified benchmarks.

\subsubsection{Splits.}
We evaluate under two protocols: (i)~\emph{Random split}: stratified 70/15/15 (9,093/1,949/1,949) with seed 42. (ii)~\emph{Lineage-disjoint split}: to strictly penalize memorization of synthetic mutation artifacts, contracts are partitioned by base origin (grouping SolidiFI \texttt{buggy\_N} variants, LISA finding entries, and parent source contracts into mutually exclusive partitions), yielding 8,349 train, 2,496 validation, and 2,146 test graphs with zero lineage overlap.

\subsubsection{Implementation.}
All models are implemented in PyTorch Geometric and trained using AdamW (learning rate $10^{-3}$, weight decay $10^{-4}$), batch size 64, OneCycleLR, over 35 epochs. Experiments were executed on an Apple M4 CPU (10 cores, 16\,GB RAM). Single 35-epoch training of GNNMHAv2 takes $348.3 \pm 37.2$\,s (versus $56.5 \pm 6.7$\,s for GCN and $67.4 \pm 1.3$\,s for GIN). Function-level inference latency is $0.21$\,ms per graph, enabling rapid prioritization prior to LLM harness generation. Dynamic execution uses Foundry Forge 1.5.1 and \texttt{solc} 0.8.30; Slither 0.11.5 provides the static heuristic baseline.

Table~\ref{tab:baselines} summarizes the baseline comparisons across both splits. Rule-based Slither yields only $0.0748$ macro-F1 due to severe alarm fatigue. Zero-shot DeepSeek-Coder-V2-Lite achieves $0.3518$ macro-F1, while fine-tuned CodeBERT reaches $0.7380$. Graph-based representations decisively outperform token sequences. \subsection{RQ2: Harness Execution Reliability}
\label{sec:rq2}

We evaluated expert-authored harnesses for five canonical reference contracts under 30 fuzzing seeds (101--130) in two modes: a directed exploit test and a 10,000-call invariant campaign, i.e., $5\times30\times2=300$ runs (Table~\ref{tab:foundry_fuzzing}). These reference contracts establish physical EVM fuzzing determinism (300/300 runs passed without non-deterministic halts) across the core vulnerability classes and an extended dynamic execution target (\textit{WeakLottery}, SWC-120; dynamic verification of front-running SWC-114 requires multi-transaction mempool simulation). In the dictionary linkage attack, an adversary armed with a vocabulary dictionary of common smart contract identifiers probes masked tokens by lexical role; 30.4\% (87/286) of identifiers are correctly resolved. DataMasker is lossless for analysis (Table~\ref{tab:datamasker_eval}): every masked contract compiles, every identifier is restored, and all 229 unique Slither detector types are reproduced without alteration. The exposure results are the more informative ones. An A2 adversary that knows the plaintext vocabulary can re-link 89.5\% of identifiers by matching occurrence frequencies, because renaming preserves the structure of the code. Pseudonymization alone is therefore \emph{not} a confidentiality mechanism for code sent to an untrusted model. It is defense-in-depth for artifacts that leave the host, and this result is the reason PRISM keeps inference local rather than masking code and sending it to a cloud LLM.

\section{Discussion and Threats to Validity}
\label{sec:discussion}

\subsubsection{What the results do and do not show.}
RQ1 shows that a compact graph model can rank functions with high precision and stable performance on unseen families. RQ2, RQ3 and RQ5 show that the execution, masking and patch-checking components are reliable. The benchmark in RQ4 exercises the filtering cascade down to concrete Foundry verification, showing that physical execution eliminates false alarms on safe contracts.

\subsubsection{Cost.}
GNN screening is linear in graph size. The LLM stage is invoked only for functions with $\Phi\ge0.5$, which bounds the number of expensive generations per contract. On an Apple M4 host, Slither analysis takes $0.42$\,s per contract, CPG extraction and GNN inference take $0.08$\,s per contract, and LLM harness generation combined with a 10,000-call Foundry campaign takes $12.4 \pm 2.1$\,s per prioritized function.

\subsubsection{Threats to validity.}
\emph{Internal.} Graph extraction depends on Slither IR; inline Yul and compilers outside 0.4.x--0.8.x may degrade CPG quality. To guard against stochastic variance, all primary static evaluation results are reported across five independent training seeds (42--46) with exact McNemar significance tests.
\emph{External.} Training in-distribution on SolidiFI and testing zero-shot on LISA-Bench without domain adaptation lowered macro-F1 from 0.8985 to 0.5157, indicating that cross-dataset transfer across disparate coding conventions remains an open challenge. The SWC registry is no longer actively maintained, and the RQ2--RQ5 contracts are small reference contracts compiled with \texttt{solc} 0.8.30, where arithmetic overflow requires \texttt{unchecked} blocks.
\emph{Construct.} Function graphs are supervised with contract-derived weak labels, which introduces label noise when injection spans cross boundaries or functions are benign; our source-span audit quantifies this limitation. Furthermore, real-world exploits may compound multiple vulnerabilities rather than a single weakness.

\subsubsection{Data availability.}
Code, trained checkpoints, the 57-contract benchmark, and harness templates are organized in the anonymous submission artifact; the reproduction package is available at \url{https://anonymous.4open.science/r/PRISM-PROJECT/}.

%======================================================================
\section{Conclusion}
\label{sec:conclusion}

PRISM shows that LLM-assisted smart contract auditing does not require sending code to a third party. A graph attention classifier over typed SSA-level function graphs ranks functions with 75.77\% macro-F1 across five SWC classes and keeps 75.75\% on unseen contract families. An open-weight model running on the audit host turns high-risk functions into Foundry harnesses, and the execution back end completed all 300 seeded harness runs reproducibly. Pseudonymization is lossless for compilation and static analysis, and our linkage analysis shows why it complements local inference rather than replacing it: 89.5\% of renamed identifiers remain linkable by frequency. Together with taxonomy-aware filtering, which reduces flagged safe contracts from 27/27 to 6/27, these results make confidential, execution-backed auditing a practical workflow.

Future work will measure the full pipeline end to end on larger real-world benchmarks, replace template repair with LLM-guided patch synthesis validated by the same five checks, and extend the graph extractor to non-EVM languages such as Move and Rust-based contracts.
