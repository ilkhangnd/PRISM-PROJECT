\begin{abstract}
Auditing unreleased smart contracts with hosted large language models (LLMs) discloses proprietary source code and business logic to the model provider. We present PRISM, an audit pipeline in which every learned stage runs on the audit host. PRISM removes secrets and reversibly pseudonymizes identifiers, converts Slither's static single assignment (SSA) intermediate representation into typed function-level code property graphs (CPGs), routes functions with a two-stage graph attention classifier, queries a locally served open-weight code LLM for vulnerability hypotheses, and checks invariant harnesses with Foundry on a local Ethereum Virtual Machine (EVM). On 12,991 public function graphs covering five Smart Contract Weakness Classification (SWC) classes, the classifier reaches $75.95\pm0.19\%$ macro-F1 on a random split and $76.31\pm0.06\%$ on a lineage-disjoint split over five seeds, at 0.21\,ms per function. Graph convolutional and graph isomorphism networks reach the same level, share at least 97\% of its errors and differ in none of 20 paired tests, which places the remaining error in contract-derived labels rather than in the encoder. On 57 benchmark contracts, pseudonymization preserves compilation and every Slither detector type, yet a frequency-aware adversary re-links 89.5\% of identifiers, so confidentiality has to come from local inference rather than from masking. Static filtering reduces flagged safe contracts from 27/27 to 6/27 while retaining 18 of 30 vulnerable contracts, and 300 seeded Foundry runs on reference harnesses complete deterministically.

\keywords{Smart contract security \and Confidential auditing \and Graph neural networks \and Local large language models \and Pseudonymization.}
\end{abstract}

\section{Introduction}
\label{sec:intro}

Smart contracts on the Ethereum Virtual Machine (EVM) hold large amounts of value in decentralized finance (DeFi), and deployed bytecode cannot be patched in place~\cite{luu2016making,atzei2017survey}. Flaws must therefore be found before deployment, usually by auditing source code that its owner has not yet released and considers proprietary~\cite{atzei2017survey}.

Large language models (LLMs) are now the most active direction in automated auditing: LLM agents audit with fine-tuned detectors or in multi-agent teams~\cite{ma2025combining,wei2025advanced}, pair with formal verification or program analysis~\cite{liu2024propertygpt,sun2024gptscan}, and derive seeds for fuzzing~\cite{lin2025promfuzz,gai2026llama}. Graph learning has advanced in parallel, up to heterogeneous graph transformers with LLM-derived features~\cite{nguyen2026mando}. Classical tools explain why learning is attractive: 97\% of 47,587 contracts were flagged by at least one static analyzer~\cite{durieux2020empirical}.

Most LLM auditors call hosted models~\cite{sun2024gptscan,liu2024propertygpt,wei2025advanced}, so the auditor transmits unreleased code, identifier names and business logic to a model provider. Provider-side confidential inference remains a research prototype~\cite{li2024confidential}, and open-weight detectors~\cite{yu2025smart} return labels without executable evidence. Masking identifiers before a hosted call is the obvious alternative, but prompt rewriting for code assistants still leaks~\cite{noah2025codecloak}, and learned models recover variable names from stripped binaries~\cite{xie2024resym,xu2025gennm}. An auditor who must keep code in house therefore faces two open questions: which parts of an LLM-assisted audit can run on commodity local hardware, and whether cheap pseudonymization would make hosted models acceptable after all.

PRISM builds on the observation that the steps of an LLM-assisted audit need different guarantees. Deciding where to look is a routing problem that a compact graph model solves in well under a millisecond per function. Proposing what may be wrong benefits from a code LLM but does not need a frontier model when its output is treated as a hypothesis. Deciding what is real requires execution. PRISM therefore places a two-stage graph attention classifier in front of a locally served open-weight code LLM and a Foundry execution back end, keeps every model and artifact on the audit host, pseudonymizes identifiers before any learned stage and restores them only in the final report. Our contributions are:

\begin{itemize}
\item A local-first audit pipeline with an explicit two-adversary threat model, in which every stage runs on the audit host and LLM hypotheses are kept separate from execution-confirmed findings (Sect.~\ref{sec:method}).
\item A function-level code property graph (CPG) over Slither's static single assignment (SSA) form with typed control- and data-flow edges, and a two-stage graph attention classifier that routes functions at $76.31\pm0.06\%$ macro-F1 on unseen contract lineages; the generic encoders we test share at least 97\% of its errors, and a label-conflict diagnostic places the remaining error in contract-derived labels (Sect.~\ref{sec:rq1}).
\item A measurement of what reversible pseudonymization preserves and leaks: masked code keeps compilation and all 229 Slither detector types, whereas a frequency adversary re-links 89.5\% of identifiers and masking lowers unguided local LLM recall from 30/30 to 13/30 (Sect.~\ref{sec:rq3}).
\item A scoped evaluation of the static and execution stages on 57 contracts: filtering clears 21 of 27 flagged safe contracts, 300 seeded Foundry runs complete deterministically, and five template patches pass five validation checks (Sects.~\ref{sec:rq2}--\ref{sec:rq5}).
\end{itemize}
The rest of the paper is organized as follows: Sect.~\ref{sec:related} reviews related work, Sects.~\ref{sec:method}--\ref{sec:results} present design, setup and results, Sect.~\ref{sec:discussion} discusses the scope of the evidence, and Sect.~\ref{sec:conclusion} concludes.

\subsubsection{Graph learning and label quality.}
A recent survey~\cite{alsunaidi2025leveraging} and early models~\cite{zhuang2021smart,liu2021combining} learn over contract graphs with normalized nodes and expert patterns, DA-GNN~\cite{zhen2024gnn} applies dual attention, ConSense~\cite{pang2025graph} combines local and global attention, and MANDO-LLM~\cite{nguyen2026mando} feeds LLM code features into heterogeneous graph transformers. PRISM's classifier builds on graph attention networks (GAT) and GATv2~\cite{velivckovic2017graph,brody2021attentive} over a homogeneous SSA-level function graph with typed edge attributes; its role is to decide which functions later stages examine, not to issue the final verdict. Studies of general vulnerability datasets show that noisy and inherited labels inflate or cap reported accuracy~\cite{croft2023data,ding2024vulnerability}, which is the effect we measure for contract-derived labels.

\subsubsection{LLMs for auditing, fuzzing and repair.}
GPTScan~\cite{sun2024gptscan} pairs GPT with static confirmation, PropertyGPT~\cite{liu2024propertygpt} and SmartInv~\cite{wang2024smartinv} generate properties or invariants for verification, LLM-SmartAudit~\cite{wei2025advanced} and iAudit~\cite{ma2025combining} organize LLM agents around the audit, and PromFuzz~\cite{lin2025promfuzz} and LLAMA~\cite{gai2026llama} guide fuzzing. Smart-LLaMA-DPO~\cite{yu2025smart} fine-tunes an 8B open model for explainable detection, which can run locally but does not execute its findings. sGuard~\cite{nguyen2021sguard} and Elysium~\cite{ferreira2022elysium} patch source or bytecode with templates.

\subsubsection{Confidential analysis.}
Provider-side protection of prompts with confidential computing is an active topic~\cite{li2024confidential}. CodeCloak~\cite{noah2025codecloak} learns prompt manipulations, including identifier replacement, that trade code leakage against suggestion quality for cloud code assistants. On the attack side, ReSym~\cite{xie2024resym} and GenNm~\cite{xu2025gennm} recover variable names and types from stripped binaries, showing that renaming does not remove the information that structure carries. PRISM takes the conservative position: inference stays local, and pseudonymization only reduces what artifacts leaving the host reveal.

Table~\ref{tab:positioning} summarizes the capabilities. PRISM is not the strongest detector or fuzzer in isolation; among the systems listed, it is the one that combines local learned inference, artifact masking and execution-based validation.

\section{PRISM Design}
\label{sec:method}


Figure~\ref{fig:pipeline} shows the pipeline; no network access is required once the model weights are installed.

\subsection{Threat Model and Pseudonymization}
\label{sec:threat}

\paragraph{Assets and trust boundary.} The asset is unreleased contract source code together with the business logic it reveals: identifier names, constants, addresses and endpoints. The trust boundary is the audit host operated by the contract owner or its auditor.

\paragraph{Adversaries.} We consider (A1) third-party model providers and network observers, to which a cloud-LLM workflow would expose code, and (A2) honest-but-curious parties that later see PRISM artifacts outside the host, such as prompt logs, generated harnesses, bug reports shared with external reviewers, or a shared inference server inside the organization. PRISM removes A1 by construction, because no inference is remote; confidentiality against A1 therefore rests on locality, not on masking. DataMasker only reduces what A2 learns from artifacts. A fully compromised audit host is out of scope, because such an adversary can read the plaintext source directly.

\paragraph{Mechanism.} PrivacyFilter first removes hard-coded private keys and application programming interface (API) keys, remote procedure call (RPC) endpoints and 20-byte addresses. DataMasker then renames user-defined identifiers of contracts, types, functions and variables, and leaves Solidity keywords, EVM built-ins such as \texttt{msg.sender} and \texttt{block.timestamp}, standard interfaces such as \texttt{IERC20}, numeric and string literals, and comments untouched. The $i$-th distinct identifier $x_i$ is mapped to
\begin{equation}
\mathcal{T}(x_i) = \texttt{prism\_}\,\sigma(x_i)\,\texttt{\_}\langle i\rangle,
\end{equation}
where $\langle i\rangle$ is a four-digit counter assigned in decreasing order of identifier length and $\sigma(x)\in\{\texttt{Type},\texttt{b},\texttt{v}\}$ keeps a coarse lexical role: \texttt{Type} for capitalized names, \texttt{b} for boolean-style names beginning with is, has or can, and \texttt{v} otherwise. $\mathcal{T}$ is a bijection; its inverse $\mathcal{T}^{-1}$ never leaves the host and is applied only to the final report. Both $\sigma$ and the counter order reveal side information, and Sect.~\ref{sec:rq3} measures what $\mathcal{T}$ preserves and what it still reveals to A2.

\subsection{Function-Level Code Property Graph}

From the pseudonymized source $S_{\mathit{mask}}$, PRISM extracts Slither's SSA IR~\cite{feist2019slither} and builds one directed graph per function, $\mathcal{G}=(\mathcal{V},\mathcal{E},X,E_{\mathit{attr}})$, whose nodes are SSA instructions.
\begin{itemize}
\item Node features $X\in\mathbb{R}^{N\times 32}$: a 13-dimensional one-hot instruction type, 10 security indicators such as low-level calls, storage reads and writes, guards and transaction-context reads, and 9 structural attributes such as in- and out-degree, loop membership and relative depth.
\item Edge attributes $E_{\mathit{attr}}\in\{0,1\}^{|\mathcal{E}|\times 4}$: a one-hot edge type among \texttt{sequential}, \texttt{branch}, \texttt{loop\_back} for control flow and \texttt{data\_dep} for def-use, so that control and data flow share one edge set.
\end{itemize}

\subsection{Two-Stage Graph Attention Classifier}
\label{sec:ranker}

Both stages use the same encoder, GNNMHAv2, which projects node features to $d=256$ dimensions and stacks $L=4$ edge-aware graph attention layers with $K=8$ heads~\cite{velivckovic2017graph,brody2021attentive}. With edge attribute $\mathbf{e}_{ij}$ and $\mathcal{N}^{+}(i)=\mathcal{N}(i)\cup\{i\}$, head $k$ of layer $l$ computes
\begin{equation}
\alpha_{ij}^{k,l}=\operatorname*{softmax}_{j\in\mathcal{N}^{+}(i)}\Big(\mathbf{a}^{k,l\top}\mathrm{LeakyReLU}\big(W_{s}^{k,l}h_i^{l}+W_{t}^{k,l}h_j^{l}+W_{e}^{k,l}\mathbf{e}_{ij}\big)\Big),
\end{equation}
\begin{equation}
h_i^{l+1}=\mathrm{ELU}\Big(\mathrm{BN}\Big(\tfrac{1}{K}\textstyle\sum_{k=1}^{K}\sum_{j\in\mathcal{N}^{+}(i)}\alpha_{ij}^{k,l}\,W^{k,l}h_j^{l}\Big)\Big)+h_i^{l},
\end{equation}
where BN is batch normalization and ELU the exponential linear unit. Residual connections and a jumping-knowledge (JK) readout, $z_i=[h_i^{1}\|h_i^{2}\|h_i^{3}\|h_i^{4}]\in\mathbb{R}^{1024}$, keep both local and multi-hop patterns. The graph embedding $g\in\mathbb{R}^{2048}$ concatenates attention pooling and mean pooling,
\begin{equation}
g=\Big[\textstyle\sum_{i}\beta_i z_i \,\Big\|\, \frac{1}{N}\sum_i z_i\Big],\qquad \beta_i=\operatorname*{softmax}_i\big(\mathbf{w}^{\top}\mathrm{ReLU}(W_p z_i)\big),
\end{equation}
and a two-hidden-layer perceptron maps $g$ to class logits. One layer costs $O(K(|\mathcal{V}|d^2+|\mathcal{E}|d))$, which is linear in graph size for fixed $d$.

Stage~A is a binary model, vulnerable or safe, trained with class-weighted, label-smoothed cross-entropy (CE). Stage~B is a five-class model trained with class-weighted focal loss on label-smoothed CE, with smoothing $\epsilon=0.05$ and $\gamma=2$:
\begin{equation}
\mathcal{L}=\frac{1}{n}\sum_{m=1}^{n}\alpha_{y_m}(1-p_{m})^{\gamma}\,\mathrm{CE}_{\epsilon}(g_m,y_m),
\end{equation}
where $p_m$ is the predicted probability of the true class and $\alpha_{y}$ the class weight. At inference, Stage~A drops functions it predicts safe, Stage~B assigns a class to the remaining ones, and PRISM orders them by the Stage-B confidence $\Phi(\mathcal{G})=\max_c p_B(c\mid\mathcal{G})$, forwarding functions with $\Phi\ge\tau$ ($\tau=0.3$) in decreasing order of $\Phi$. With five classes $\Phi\ge0.2$ always, so $\tau$ mainly removes near-uniform predictions and the forwarded order is what matters.

\subsection{Local LLM Audit, EVM Execution and Repair}
\label{sec:llm}

\paragraph{Local LLM audit.} The masked source and the routed functions, each with its predicted class and $\Phi$, are passed to an open-weight code LLM, DeepSeek-Coder-V2-Lite-Instruct, a 16B-parameter mixture-of-experts model with 2.4B active parameters~\cite{zhu2024deepseek}. It is served on the host by Ollama\footnote{\url{https://ollama.com}; the quantized model occupies 8.3\,GiB on disk.} with temperature 0.1 and at most 4,096 generated tokens. The prompt asks for a structured finding per suspected weakness: weakness type, severity, affected function, attack path, exploit scenario and fix.

\paragraph{Execution.} Independently of the LLM output, PRISM runs a local Foundry back end without network calls. For the evaluated classes, invariant harnesses follow class templates, for example balance conservation for reentrancy and privileged rejection for access control, and are fuzzed locally. In this paper the harnesses are expert-written reference harnesses (Sect.~\ref{sec:rq2}) and a template replay over the benchmark (Sect.~\ref{sec:rq4}). An execution finding is reported as confirmed only if an assertion fails with a concrete counterexample trace; LLM findings are reported as unconfirmed hypotheses.

\paragraph{Repair and report.} A template-based repair module proposes a patch for each confirmed finding, which must pass five checks (Sect.~\ref{sec:rq5}). LLM hypotheses and execution results are merged and deduplicated by function and weakness type, keeping their confirmation status, and identifiers are restored through $\mathcal{T}^{-1}$ only in the final report.

\section{Experimental Setup}
\label{sec:setup}

\subsubsection{Research questions (RQs).}
RQ1: How accurately does the classifier label vulnerable functions on seen and unseen contract lineages, and how does it compare with other graph learners?
RQ2: Does the local EVM back end execute harnesses reliably and reproducibly?
RQ3: Does pseudonymization preserve analysis utility, and what does it still reveal?
RQ4: How far do taxonomy- and severity-aware filters reduce alarms on safe contracts without losing vulnerable ones?
RQ5: Do template patches block exploits while preserving interfaces?

\subsubsection{Dataset.}
We extract 12,991 function-level CPGs with at least three nodes from three public sources: SmartBugs Wild~\cite{durieux2020empirical} (1,179 graphs), the SolidiFI benchmark~\cite{ghaleb2020effective} (8,105 graphs) and LISA-Bench\footnote{AgentLISA: LISA-Bench: Smart contract vulnerability detection benchmark. \url{https://github.com/agentlisa/bench} (2025), accessed September 2026.} (3,707 graphs), a collection of professional audit findings. The graphs cover five Smart Contract Weakness Classification (SWC) classes: Reentrancy (SWC-107, 2,475), Integer Overflow (SWC-101, 2,392), Access Control (SWC-105, 2,026), Unchecked Return Value (SWC-104, 2,983) and Timestamp or Transaction-Order Dependence (SWC-114, 3,115). Graphs of the remaining source categories, denial of service and delegatecall, are excluded from the five-class task.
Labels follow a contract-derived weak-supervision policy: SmartBugs and SolidiFI functions inherit the label of their contract, and LISA-Bench functions inherit the label obtained by keyword mapping of the finding text. We audited this choice on SolidiFI: of 9,369 injected bug spans in its 350 BugLog contracts, 4,947 map uniquely to a function body, and a strictly span-mapped subset would keep only 2,580 graphs with two Reentrancy and two timestamp dependence examples, too few for a five-class task. Stage~A is trained on a larger binary corpus of 24,454 graphs that also contains the excluded categories and graphs labeled safe, with labels 0--7 treated as vulnerable and label 8 as safe.

\subsubsection{Splits.}
We use two frozen protocols for the five-class classifier. The random split is stratified 70/15/15 (9,093/1,949/1,949 graphs). The lineage-disjoint split partitions contracts by origin so that SolidiFI \texttt{buggy\_N} variants, functions from the same LISA-Bench finding, and functions from the same imported source contract never cross partitions, giving 8,349/2,496/2,146 graphs with zero lineage overlap. Stage~A uses a frozen binary 70/15/15 split (17,118/3,667/3,669; test: 3,132 vulnerable, 537 safe).

\subsubsection{Baselines.}
To isolate the effect of the encoder, we train graph convolutional (GCN) and graph isomorphism (GIN) networks as well as GAT and GATv2 on the same graphs, node features, splits and training budget; GAT and GATv2 do not use edge attributes. As a rule-based reference, Slither~0.11.5 is mapped to the five classes through its detector names, for example \texttt{reentrancy-eth} to Reentrancy and \texttt{unchecked-lowlevel} to Unchecked Return, and a function that triggers no mapped detector is assigned the majority training class.

\subsubsection{Implementation.}
Models are implemented in PyTorch Geometric and trained with AdamW (learning rate $10^{-3}$, weight decay $10^{-4}$), batch size 64 and OneCycleLR for up to 35 epochs with early stopping on validation macro-F1 (patience 15). GNNMHAv2, GCN and GIN are trained with five seeds (42 to 46); GAT and GATv2 with seed 42. Experiments run on an Apple M4 CPU with 10 cores and 16\,GB RAM. One 35-epoch training run of GNNMHAv2 takes $348.3\pm37.2$\,s, compared with $56.5\pm6.7$\,s for GCN and $67.4\pm1.3$\,s for GIN, and inference takes 0.21\,ms per function graph. Execution uses Foundry Forge~1.5.1 and \texttt{solc}~0.8.30.

Table~\ref{tab:baselines} compares the classifier with graph baselines. GNNMHAv2 reaches $0.7595\pm0.0019$ macro-F1 on the random split and $0.7631\pm0.0006$ on the lineage-disjoint split, with macro-precision $0.887\pm0.005$ and macro-recall $0.725\pm0.001$ on the random split; macro-F1 exceeds accuracy because the large Unchecked Return class has low precision while the smaller classes are predicted precisely. The mapped Slither reference scores $0.0748$ because its detectors fire on few function slices under our label mapping. Over five fresh seeds, Stage~A reaches $88.62\pm0.24\%$ accuracy, with $87.82\pm0.32\%$ vulnerable recall and $93.26\pm0.61\%$ safe specificity ($n=3{,}669$).

The more informative result is that all graph learners converge to the same level. On both splits, GCN, GIN, GAT, GATv2 and GNNMHAv2 lie within 0.5 macro-F1 points of each other. In 20 paired exact McNemar tests between GNNMHAv2 and GCN or GIN over two splits and five seeds, no difference is significant even without multiple-comparison correction (all $p>0.16$), the paired models disagree on at most 22 test functions per run, and between 97.4\% and 99.6\% of GNNMHAv2's errors are shared with the baseline. Pairwise Jaccard error overlap exceeds 96.5\%, and 493 of 520 errors (94.8\%) are shared across all five architectures. When models of different design make the same errors, label noise is a more plausible limit than encoder capacity. A structural-label-conflict diagnostic supports this: 6.2\% of random-split test graphs match a training graph with a conflicting label because of contract-level inheritance; on these graphs accuracy falls to 7.9\%, whereas on conflict-free graphs it reaches 78.7\%.

The per-class view in Fig.~\ref{fig:confusion} shows where the shared errors go. Precision is 0.95 to 1.00 for the four specific classes, but their recall is 0.56 to 0.73, and 490 of the 505 errors are predictions of Unchecked Return (precision 0.47, recall 0.99), whose SSA signature, an external call followed by an unused result, is the most generic. The model therefore rarely confuses two specific weaknesses. It assigns functions that carry no class-specific evidence to the most generic class, which is what contract-derived labels produce when a contract's label is inherited by functions that do not contain the flaw. Consistently, five-seed top-2 accuracy is 0.8086, so the second-ranked class recovers only 25.6\% of the errors: most errors are not near misses.

\subsection{RQ2: Execution Back-End Reliability}
\label{sec:rq2}

We executed expert-written reference harnesses for five case-study contracts under 30 fuzzing seeds (101 to 130) in a directed exploit test and a 10,000-call fuzzing campaign, for $5\times30\times2=300$ runs. The targets are SimpleDAO (SWC-107), TokenSale (SWC-101), UnprotectedVault (SWC-105), UncheckedBank (SWC-104) and TimestampLock (SWC-114). All 300 runs passed without timeouts, with mean directed and fuzzing latencies of 190.26 and 202.75\,ms, and directed transaction gas was deterministic at 77,558, 39,648, 48,550, 27,202 and 39,827, respectively. A seed-42 integrated trace ran masking, preprocessing, GNN routing, a bounded local LLM audit and the reference tests for all five cases, and every stage completed. This shows that the local stages run together reproducibly; because the harnesses are hand-written, it does not measure how often generated harnesses find bugs.

\paragraph{Utility.} Table~\ref{tab:datamasker_eval} shows that DataMasker is lossless for compilation and restoration: every masked contract compiles with \texttt{solc}, and $\mathcal{T}^{-1}$ restores every contract exactly. For static analysis, all 229 contract-level Slither detector types raised on plaintext code are preserved on masked code, with six further types added by naming conventions. For the LLM stage, we ran a taxonomy-guided audit over the five SWC classes without GNN hotspots. On raw code it recalls 30/30 vulnerable contracts with 11/27 (40.7\%) safe specificity, so unconstrained inspection raises many false alarms on benign patterns. On pseudonymized code, recall drops to 13/30 (43.3\%) while safe specificity rises to 19/27 (70.4\%): once role-revealing names such as \texttt{owner} are masked, a text-only audit loses most of its cues. For weaknesses expressed through EVM built-ins such as \texttt{block.timestamp} and external \texttt{.call}, raw and masked audits give identical predictions (Jaccard $J=1.00$). Masking thus costs recall exactly where the model relies on identifier semantics, which motivates structural hotspots from the graph classifier.

\paragraph{Exposure.} We quantify two A2 adversaries. The dictionary measure counts identifiers whose plaintext name is one of 32 common Solidity and DeFi terms such as \texttt{owner}, \texttt{balance} and \texttt{withdraw}; an adversary who guesses these terms from the role of a pseudonym recovers at most 30.4\% of identifiers. The frequency adversary knows how often each plaintext identifier occurs in the contract, for example from an earlier version or a leaked excerpt, ranks identifiers and pseudonyms by occurrence count, and aligns the two rankings. Because $\mathcal{T}$ renames one-to-one and preserves occurrence counts, only ties stop it, and it re-links 89.5\% of identifiers. This upper bound assumes strong side knowledge, but it shows that renaming preserves code structure, so pseudonymization alone is not a confidentiality mechanism for code sent to an untrusted model~\cite{xie2024resym,xu2025gennm,noah2025codecloak}; it is defense in depth for artifacts that leave the host.

\subsection{RQ5: Patch Validation}
\label{sec:rq5}

For the five case-study contracts with exploit harnesses (Sect.~\ref{sec:rq2}), template repair produced one patch each. Each patch passed five checks: (1)~compilation with \texttt{solc}~0.8.30; (2)~minimal change, at most 25\% of lines measured on the abstract syntax tree; (3)~the original exploit harness now reverts; (4)~the 10,000-call fuzzing campaign still passes; and (5)~function selectors and storage layout are unchanged, which preserves the external application binary interface and proxy storage layout.

\section{Discussion and Limitations}
\label{sec:discussion}

\subsubsection{Scope of the evidence.}
Graph screening costs 0.21\,ms per function, negligible next to one Foundry run of about 0.2\,s, and the LLM is invoked only for functions with $\Phi\ge\tau$. The stages are evaluated separately. We do not report within-contract ranking metrics such as recall at $k$, a joint accuracy for the Stage-A and Stage-B cascade, or the recall of the masked LLM when its prompt includes GNN hotspots; the last is the measurement that would show whether structural routing recovers the recall that masking removes in Sect.~\ref{sec:rq3}. Execution and repair are evaluated on five single-contract cases with expert-written harnesses, so they establish feasibility and determinism rather than bug-finding frequency, and automated harness synthesis for multi-file mainnet contracts remains open. The encoder comparison covers generic graph learners; contract-specific models such as MANDO-LLM~\cite{nguyen2026mando} and fine-tuned local LLMs~\cite{yu2025smart} were not retrained on our labels.

\subsubsection{Threats to validity.}
Construct validity: function graphs inherit contract-derived labels, so benign functions are counted as positives, which bounds classification accuracy; the 57 benchmark labels follow injection templates rather than manual spans, and SWC-114 targets are timestamp proxies. Internal validity: DataMasker leaves comments and string literals in clear, and NatSpec comments can describe business logic; its counter order and role prefix leak length rank and lexical role, which a keyed random permutation would remove. Slither IR extraction may degrade on inline Yul. External validity: the benchmark contracts are small reference implementations under \texttt{solc}~0.8.30, and transfer across data sources was not evaluated.

\subsubsection{Data availability.}
Code, configurations, frozen split manifests, result files and reference harnesses are available in an anonymized repository: \url{https://anonymous.4open.science/r/PRISM-PROJECT/}.

\section{Conclusion}
\label{sec:conclusion}

This paper presented PRISM, a smart contract audit pipeline that keeps every model and artifact on the audit host and separates LLM hypotheses from execution-confirmed findings. Its two-stage graph attention classifier routes functions at $76.31\pm0.06\%$ macro-F1 on unseen contract lineages in 0.21\,ms per function, and the agreement of generic graph encoders on the same errors shows that contract-derived labels, not model capacity, limit function-level accuracy. Reversible pseudonymization preserves compilation and static analysis, yet a frequency adversary re-links 89.5\% of identifiers, so confidentiality has to come from local inference. Static filtering reduces flagged safe contracts from 27/27 to 6/27, execution refutes the six residual alarms, and reference harnesses and template patches run deterministically on commodity hardware.

Future work will measure the masked LLM audit with GNN hotspots and the full cascade end to end on larger production benchmarks, replace contract-derived supervision with function-level ground truth, mask comments and randomize pseudonym indices, and extend template repair to automated harness and patch synthesis.
